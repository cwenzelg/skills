# Folder template

One design system per product direction, in the project's own workspace (next to `design/`):

```
design-system/<name>/                 # e.g. design-system/harbor/
  system.json                         { name, modes, fontImports, roles: { ground, text } }
  DESIGN.md                           entry point: character, always/never rules, open points (each «entschieden nach» R1-R6 or «für <owner>»), exceptions (R1a), file map, status (< ~120 lines); `references/open-points.md`
  llms.txt                            one line per file, for agents
  tokens/                             DTCG 2025.10 - the ONLY source of values
    primitives.tokens.json            tier 1: every raw value, each with $extensions["skill.design-system"].source
    semantic.light.tokens.json        tier 2: roles (bg.*, text.*, accent.*, type.*, shape.*, elevation.*, motion.*)
    semantic.dark.tokens.json         same paths as light - check-system.mjs enforces it
    components.tokens.json            tier 3: <component>.<part>[.<state>] -> semantic roles only
    brands/<brand>.tokens.json        a customer scheme: colour primitives or colour brand.* slots only; declares its modes
  build/                              GENERATED by build-tokens.mjs - tokens.css, tokens.resolved.json; never edit
  foundations/                        one file per foundation, fixed grid: What · roles/scale · Do · Don't · CSS
    color.md  typography.md  elevation.md  iconography.md   (required: the shared four)
    grounds.md (mesh, gradients, glass)  glass.md  layout.md  motion.md   (as the system needs)
  components/
    <name>.md                         fixed grid: Purpose · Anatomy · Tokens · States · Do · Don't
    <name>.html                       snippet using var(--...) only - the specimen shows it
  specimen/
    index.html                        GENERATED by specimen.mjs
    APPROVED.md                       who approved, when, their words (references/approved-template.md)
  reference/
    light/*.png  dark/*.png           the approved screens - the visual anchor
    dont/*.png + README.md            typical mistakes, one line why
  checks/
    contrast-pairs.json               every text/background pair, glass with its backdrop
    CHECKLIST.md                      the release checklist
```

The specimen page's sections are fixed too: `references/specimen-structure.md` (the section contract
every system follows and `check-system.mjs` enforces).

Start from the skill's `assets/starter/` (a complete, minimal, working system with placeholder
sources). `check-system.mjs` fails until every `TODO` source is replaced with where the value was
really read.

## Naming

- Paths are lowercase, dot-separated; the CSS name is the path with dashes: `bg.ground` -> `--bg-ground`.
- Primitives describe the value (`color.violet.300`), roles describe the use (`text.muted`),
  components describe the part (`chip.glass.bg`, `button.hover.bg`).
- A state is a path segment from: default, hover, pressed, active, focus, disabled, selected,
  error, loading, empty - check-system.mjs matches these against the spec's States section.
- Never put a primitive and a role on the same path.

## What DTCG cannot express

Mesh grounds, angled or radial gradients, glass (backdrop blur + tint + rim light) go into
`$extensions["skill.design-system"]`:

```json
"ground": {
  "$type": "color",
  "$value": "{color.violet.50}",
  "$extensions": { "skill.design-system": {
    "source": "reference/light/answer-screen.html, body background",
    "css": "radial-gradient(60% 50% at 0% 0%, {color.peach.200} 0%, transparent 70%), radial-gradient(50% 50% at 100% 20%, {color.violet.200} 0%, transparent 70%), {color.violet.50}",
    "stops": ["{color.peach.200}", "{color.violet.200}", "{color.mint.200}", "{color.violet.50}"]
  } }
}
```

`$value` is the flat fallback colour; `css` is what is emitted; `stops` are every colour the
background passes through - contrast.mjs measures glass and text over each of them.
