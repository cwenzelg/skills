# Specimen structure: the section contract

Every design system looks the same from the outside, so a reviewer, a designer and the Cluster Console
find the same thing in the same place. The structure is taken from the two template systems - Loop
Studio and Tap2Link Harbor - which share exactly this. It is enforced by `scripts/check-system.mjs`
(`lib/contract.mjs` holds the list) and rendered by `scripts/specimen.mjs`; never hand-build a specimen.

## The sections of `specimen/index.html`, in order

The page opens with the title block (`#top`: title, character lede, counts), then:

| # | id | Section | When | Shows |
|---|---|---|---|---|
| 1 | `character` | Character and rules | always | DESIGN.md: the character in words, the always/never rules |
| 2 | `open` | Open points | when DESIGN.md has an "Open points ..." section with items | the questions a human decides, as a table |
| 3 | `colour` | Colour | always | every colour role per mode (and brand) with its source and a derived flag |
| 4 | `recipes` | Grounds and effects | when a ground, gradient, glass or blur recipe exists | each recipe in every mode on the system's own ground |
| 5 | `type` | Typography | always | the typefaces in their real fonts and the type scale |
| 6 | `shape` | Shape | always | radii, shadows, spacing and other dimensions |
| 7 | `foundations` | Foundations | always | one tile per `foundations/*.md` (colour, typography, elevation, iconography, ...) |
| 8 | `components` | Components | always | every component in every mode and brand, all states, next to its spec |
| 9 | `reference` | Reference screens | always | the approved screens per mode, then the typical mistakes (`reference/dont/`) |
| 10 | `files` | Files and checks | always | DESIGN.md "Files" and "Status": where everything is, what is green |

A conditional section is required exactly when it applies to THIS system: the check compares the page on
disk with what a fresh `specimen.mjs` run produces. Nothing is added or reordered by hand.

## What `check-system.mjs` fails on (besides the token rules)

- `specimen/index.html` missing, **hand-made** (no "Generated by the design-system skill's specimen.mjs"
  footer) or **missing a section** a fresh run produces: regenerate with `node specimen.mjs <system>`.
- A template file missing: `system.json`, `DESIGN.md`, `llms.txt`, the four `tokens/*.tokens.json`,
  `build/tokens.css` + `build/tokens.resolved.json`, `foundations/{color,typography,elevation,iconography}.md`,
  `checks/CHECKLIST.md`, `checks/contrast-pairs.json`.
- `DESIGN.md` without `## Character`, `## Rules (always / never)`, `## Files`, `## Status`.
- `reference/dont/` without an image; a component spec without its `.html` snippet; no reference image
  for a mode.

## Where it is read

`completeness(dir)` (exported by `check-system.mjs`, never throws) returns `{ complete, gaps[], sections[] }`;
the Cluster Console shows it on `/design` (badge «vollständig» / «N Lücken») and on a system's page (header,
gap list, a section navigation in this order that jumps into the specimen). The cluster check
`scripts/design-systems-check.mjs` runs it over every design system of every project and lists the red ones
in the Monday review.

## Adding a section

A new section is a decision for ALL systems: add it to `SPECIMEN_SECTIONS` in `lib/contract.mjs`, render it in
`specimen.mjs`, bring the starter and the existing systems up to it in the same change, and add a test.
